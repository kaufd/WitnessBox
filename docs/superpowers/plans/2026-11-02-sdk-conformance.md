# План: набор совместимости SDK (`ebt-check --conformance`)

> **Для исполнителя-агента:** обязательный sub-skill — superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans. Шаги отмечаются чекбоксами (`- [ ]`).

**Статус: по триггеру.** План выполняется, когда появится проект на языке без SDK (Python, Go, Swift, C# и т. п.) или решение о Python SDK. До этого он не выполняется: по YAGNI три существующих SDK уже сверяются общим golden в `make test-sdk`.

**Цель:** новый язык подключается без правки ядра и без знания внутренностей тестов Java, TS и Dart. Автор SDK получает из поставки описание сценария и отрицательных случаев, а одна команда отвечает, совместима ли реализация.

**Архитектура:**
- Контракт SDK (D25) — `ev()`, формат строки, допустимые значения и golden. Он переносится из тестов в данные поставки: `resources/conformance/`.
- Проверка в два слоя:
  1. golden-сценарий: SDK записывает его, файл сравнивается байт в байт;
  2. отрицательные случаи: SDK пытается записать каждое недопустимое значение и сообщает, отклонено ли оно и с каким путём поля, а затем пишет пробную запись, по `seq` которой видно, что отказы не тронули счётчик.
- Харнес на стороне языка пишет два файла. `ebt-check --conformance` их проверяет.
- Существующие тесты Java, TS и Dart переводятся на эти данные. Тем самым набор доказан на трёх реализациях до первого нового языка.

**Стек:** Python 3.11+ stdlib (чекер), JSON-данные, существующие SDK-тесты.

**Источник требований:** обсуждение 2026-11-02 (пункт 5 списка развития); D20, D25, D27, D28; [docs/sdk.md](../../sdk.md) — таблица допустимых значений и оговорки эквивалентности.

## Глобальные ограничения

- Формат свидетельств, golden и байты существующих SDK не меняются: правка `Ebt.java`, `ebt.ts`, `ebt.dart` даёт потребителям `pinned_drift` (D25).
- Чекер не импортирует SDK и не исполняет код на других языках: `--conformance` читает только файлы, которые записал харнес.
- Runtime без зависимостей.
- Новый флаг `ebt-check` — совместимое изменение: версия minor, запись D49.

## Фокус ревью

1. Язык, где вида значения нет (`undefined` вне JS, `BigDecimal` вне Java): харнес отмечает случай как `n/a` с причиной. Отсутствие строки о случае — ошибка, а не молчаливый пропуск.
2. SDK отклонил значение, но `seq` вырос: пробная запись после отрицательных случаев имеет `seq` 1, иначе — несовместимость «отказ испортил счётчик».
3. Путь поля в ошибке отличается форматом (`data.v.0.x` вместо `data.v[0].x`): несовместимость, потому что путь — часть контракта D20/D27.
4. Golden совпал, но в файле лишний перевод строки или BOM: сравнение байт в байт, BOM — несовместимость.
5. Тот же `cases.json` прочитан старым харнесом после добавления случая: новый идентификатор без ответа — несовместимость с понятным сообщением «нет ответа на случай <id>».

- Производит: `cases.json`:
  - `{"format": 1, "golden": {"scope": "golden", "calls": [...]}, "negative": [{"id", "kind", "path"}...]}`;
  - `calls` — вызовы `ev()` golden-сценария данными. `kind` — языконезависимое имя вида значения: `fraction`, `nan`, `infinity`, `unsafe_integer`, `undefined`, `array_hole`, `non_string_key`, `date`, `set`, `arbitrary_object`, `function`, `bigint`;
  - `path` — ожидаемый путь поля, например `data.v[0].x`.
- Набор `kind` берётся из таблицы «Допустимые значения» `docs/sdk.md`; новых видов не вводится.

## Что не входит

- Сам SDK для нового языка — отдельный план под конкретный проект, его проверка — этот набор.
- `traced()` и другие необязательные удобства (D25).
- Сериализация дробей, времени и конкурентности сверх соглашений D28.
